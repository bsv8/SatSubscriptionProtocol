# SSP 身份与长连接边界设计

## 1. 责任边界

SSP 是运行在外层已认证长期连接上的业务协议。外部应用负责建立连接、认证远端公钥、
加密、分帧、超时、断线、连接注册和实际发送；SSP SDK 只处理完整 Wire 和业务状态。

~~~text
外部长期连接应用
  ├── 认证 remote_public_key
  ├── 读取一个完整 SSP Wire
  ├── 为每条 Stream 复用一个 SSP Session
  └── 按请求结果用串行 writer 写回响应
        └── SSP SDK
              ├── 外层解析并读取 request_id
              ├── 登记/抑制同 Stream 重复编号
              ├── 调用 Backend 或 Dispatcher
              └── 产生 ActionResult / SubscriptionsResponse
~~~

SSP 不自行建立网络、不认证身份、不管理在线连接、不执行 SPI，也不操作 Stream 的关闭或
重置。

## 2. 身份输入

外部应用向 SDK 交付：

~~~go
type AuthenticatedPayload struct {
    RemotePublicKey protocol.PublicKey // 已认证长期连接提供的公钥
    Payload         []byte             // 一个完整 SSP Wire
}
~~~

SDK 只检查公钥为 33 字节且以 02/03 开头的压缩公钥形状，不验证 secp256k1 曲线点。
真实认证必须在进入 SSP 前完成。SSP payload 不能自报、覆盖或切换身份，订阅状态按该公钥
的 exact bytes 保存。

## 3. Stream、Session 和请求结果

每条 Stream 建立一个 Session。收到完整 Wire 后，Session 先同步完成外层解析和
request_id 登记，再执行具体业务：

~~~text
不同 request_id → 可以并行执行，响应按完成顺序产生
相同 request_id → 只有第一次执行，之后静默丢弃且没有响应
~~~

Session 只保护编号集合，不把不同编号的 Backend/Dispatcher 调用串行化。每条 Stream 的
编号集合独立，最多登记 65536 个不同编号。超过上限返回本地 SESSION_LIMIT，不伪造
ActionResult；Stream 是否结束由外部应用决定。Stream 更换后相同编号可以再次执行。

外部应用负责一个串行 writer：多个异步调用的响应必须完整写出，不能让字节交错。客户端
按响应里的 request_id 关联结果，不依赖输入顺序或响应顺序。存在业务依赖时，例如订阅
成功后查询列表，应先收到对应 ActionResult 再提交查询。

## 4. 调用契约

~~~text
已认证连接收到 Wire
  → 取得该连接的 remote_public_key
  → session.HandleMessage(Wire)
      ├── Publish / Subscribe / Unsubscribe 成功：ActionResult
      ├── SubscriptionsRequest 成功：SubscriptionsResponse
      ├── 可识别编号的业务失败：失败 ActionResult，Stream 继续
      └── 外层/编号/身份/Session 错误：本地错误，不伪造响应
  → 外部应用按 request_id 和 HasResponse 写回同一连接
~~~

成功响应的 charged_amount 是 Backend/Dispatcher 已实际扣除的精确十进制字符串。失败
固定为 "0"。普通业务失败不会关闭整条 Stream；SDK 不调用 Close、不 reset 连接。

## 5. 广播和 Publish 语义

服务端把 Publish 事件交给 Dispatcher：

~~~text
request_id
publisher public key
channel
content_json exact bytes
完整 Publish Wire exact bytes
~~~

Dispatcher 使用订阅集合规则匹配在线身份，并由外部应用完成发送。同一身份对一条 Publish
最多交付一次；某个接收者离线、超时或写入失败，不改变发送者的成功 ActionResult，也不
退款。Publish 成功只承诺服务端已接受、已扣费并开始广播，不承诺任何收件人已收到。

## 6. SPI 与原子收费边界

SSP Wire 不携带余额、价格、货币名称、支付凭证或 SPI 字段。外部应用可以在同一已认证
身份上使用 SPI，但不把 SPI Wire 交给 SSP。

Backend/Dispatcher 必须保证：

- Subscribe/Unsubscribe 的检查、收费和状态写入是同一事务；
- SubscriptionsRequest 的收费和列表读取来自同一事务快照；
- Publish 的收费和“接受并开始广播”是同一不可分割动作；
- 失败不收费、不留下部分状态；
- SPI Collect 与 SSP 收费并发触碰同一账户时有行锁或等价串行化。

SDK 不解析配置文件、不调用 SPI、不实现事务；它只校验成功返回的 charged_amount 和
订阅列表。

SPI 的 `balance`/`amount` 是最小单位的 `uint64`，而 SSP 的 `charged_amount` 可以是
该单位的小数。应用层必须使用固定 scale 的整数账本进行换算，规则见
[SPI 集成与金额换算](./SPI集成与金额换算.md)；这不改变 SSP Wire。

## 7. 错误边界与 cause

连接认证、分帧、断线、写入和网络错误属于外部应用。SSP 的本地错误包括 Wire 格式、
channel、JSON、身份、Backend/Dispatcher 和 Session 状态分类。

可安全读取 request_id 的 Backend/Dispatcher 失败会返回失败 ActionResult，同时保留本地
cause：Go 可通过 Result.Cause 使用 errors.Is/As 找到稳定分类和原错误，业务失败时返回
error 为 nil；只有无法安全构造响应的错误才返回非空 error。TypeScript 可通过
SessionResult.cause 的 SSPError.cause 找到原异常。cause 不进入 ActionResult，不向对端
泄漏堆栈或数据库文本。

外层损坏、request_id 缺失/长度错误、认证失效、Session 上限或已关闭状态无法安全构造
响应，只返回本地错误；SDK 不自行结束 Stream。

## 8. 明确不实施

- HTTP、WebSocket、WebRTC、bitcoin-libp2p Transport/adapter 或 Stream handler；
- 网络握手、协议 ID、长度前缀、分帧、加密、心跳、重连、backpressure 和写队列；
- 在线连接注册、真实发送、慢消费者清理和连接生命周期；
- 收件人列表、送达回执、退款、历史、离线队列、补发和结果缓存；
- 跨 Stream 去重、断线结果恢复和 SPI 类型依赖。
