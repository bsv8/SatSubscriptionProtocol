# SSP：简单订阅广播协议

SSP 用于按频道发布和订阅 JSON 广播。

- Channel 不需要创建、注册、删除、所有者或配置。
- 向一个 channel 发布或订阅一个 channel 时，该 channel 自然存在。
- Channel 使用名称精确匹配，`*` 表示订阅所有 channel。
- 发布内容只有 channel name 和 JSON content。
- SSP 不定义历史消息、离线队列、确认、重试或计费。
- 支付和找回由上游 SPI 处理，不进入 SSP 报文。
- 身份认证由外层完成，规则见《身份与传输层设计》。
- 正式消息使用确定性 CBOR 编码，JSON 示例只用于说明业务语义。

## 1. Publish

```jsonc
{
  "protocol": "SSP",       // 协议名称
  "version": 1,             // 协议版本
  "type": "publish",       // 发布，同时也是订阅者收到的广播类型
  "channel": "news",       // channel name
  "content": {              // 任意合法 JSON 内容
    "title": "hello"
  }
}
```

规则：

- `channel` 必须是非空字符串。
- `channel` 区分大小写，不进行裁剪或 Unicode 归一化。
- `*` 是保留名称，不能用于 Publish。
- 服务程序将 Publish 交付给订阅该 channel 或订阅 `*` 的当前在线订阅者。
- 同一订阅者对一条 Publish 最多接收一次。
- Publish 不保存历史；之后才订阅的客户端不会收到之前的内容。

## 2. Subscribe

```jsonc
{
  "protocol": "SSP",
  "version": 1,
  "type": "subscribe",
  "channel": "news"        // 也可以是 "*"
}
```

规则：

- 重复 Subscribe 是幂等操作。
- Subscribe 普通 channel 时，将其加入已订阅集合。
- Subscribe `*` 时，已订阅集合规范化为仅包含 `*`。
- 已订阅 `*` 时再 Subscribe 普通 channel，不改变集合。
- 可以在任何 Publish 之前订阅一个 channel。

## 3. Unsubscribe

```jsonc
{
  "protocol": "SSP",
  "version": 1,
  "type": "unsubscribe",
  "channel": "news"        // 也可以是 "*"
}
```

规则：

- 对未订阅的普通 channel 执行 Unsubscribe 是幂等操作。
- Unsubscribe 普通 channel 时，将其从已订阅集合移除。
- 已订阅 `*` 时，Unsubscribe 普通 channel 不改变集合；SSP 不定义排除列表。
- Unsubscribe `*` 时清空全部订阅。

## 4. Subscriptions 请求

```jsonc
{
  "protocol": "SSP",
  "version": 1,
  "type": "subscriptions"
}
```

服务程序返回当前已认证订阅者的已订阅列表。

同一条有序传输流中的消息必须按接收顺序处理。因此，在 Subscribe 或 Unsubscribe
之后发送 Subscriptions 请求，可以确认更新后的状态。

## 5. Subscriptions 返回

```jsonc
{
  "protocol": "SSP",
  "version": 1,
  "type": "subscriptions",
  "channels": ["alerts", "news"]
}
```

规则：

- `channels` 表示已订阅集合，不表示当前存在的 channel 列表。
- 普通 channel 按其 UTF-8 字节升序返回。
- 没有订阅时返回空数组。
- 全频道订阅只返回 `["*"]`，不展开实际 channel。
- 返回中不能同时出现 `*` 和普通 channel。

## 6. 非目标

SSP v1 不定义：

- channel 管理、枚举、元数据或权限模型
- 发布者信息、消息 ID、时间戳或消息签名
- 历史消息、离线消息、消息确认或重放
- 正则、前缀、层级通配或 `*` 排除项
- 价格、余额、支付凭证、套餐或有效期
- SPI 的支付和找回流程

## 7. V1 固定限制

实现必须使用以下固定限制，Go 与 TypeScript 数值一致：

| 常量 | 数值 | 中文含义 |
|---|---:|---|
| `MaxWireBytes` / `MAX_WIRE_BYTES` | 1048576 | 完整 Wire 最大字节数 |
| `MaxDocumentBytes` / `MAX_DOCUMENT_BYTES` | 1048512 | 内层 document 最大字节数 |
| `MaxChannelUTF8Bytes` / `MAX_CHANNEL_UTF8_BYTES` | 256 | channel UTF-8 最大字节数 |
| `MaxContentJSONBytes` / `MAX_CONTENT_JSON_BYTES` | 1048000 | content_json 原始字节最大长度 |
| `MaxSubscriptions` / `MAX_SUBSCRIPTIONS` | 1024 | 单身份订阅集合最大元素数 |

超出限制的输入必须按 SDK 稳定错误分类拒绝，不能使用代码中未写入文档的隐式上限。
