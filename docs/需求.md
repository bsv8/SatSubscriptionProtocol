# SSP V1 需求与协议语义

SSP 用于按 channel 发布和订阅 JSON 广播。身份认证由外层长期连接完成，支付与找回由
上游 SPI/计费应用完成；SSP 核心只定义 Wire、订阅状态和动作结果。

## 1. 请求和响应

正式 Wire 不是下面的 JSON；JSON 只用于解释字段。正式编码是 deterministic CBOR 外层
[wire_version, wire_kind, document_cbor]，所有客户端请求的第一字段都是固定 32 字节
request_id（请求编号）。

~~~jsonc
// Publish（Kind 1）
{
  "request_id": "32-byte-id",       // 同一 Stream 内关联请求和结果
  "channel": "news",                // 普通 channel，不能是 "*"
  "content_json": "raw UTF-8 bytes" // 完整 JSON 原始字节
}

// Subscribe / Unsubscribe（Kind 2 / 3）
{
  "request_id": "32-byte-id",       // 请求编号
  "channel": "news"                 // 也可以是 "*"
}

// SubscriptionsRequest（Kind 4）
{
  "request_id": "32-byte-id"        // 查询编号
}
~~~

服务端响应：

~~~jsonc
// SubscriptionsResponse（Kind 5）
{
  "request_id": "32-byte-id",       // 原样回显查询编号
  "charged_amount": "0.001",        // 本次实际扣费，精确十进制字符串
  "channels": ["alerts", "news"]    // 规范排序的当前订阅集合
}

// ActionResult（Kind 6）
{
  "request_id": "32-byte-id",       // 原样回显请求编号
  "success": true,                  // 动作是否成功
  "charged_amount": "0",            // 成功为实际扣费，失败固定为 "0"
  "error_code": ""                  // 成功为空，失败为固定错误码
}
~~~

Publish、Subscribe、Unsubscribe 成功各返回一条 ActionResult；SubscriptionsRequest 成功
只返回一条 SubscriptionsResponse。响应可以乱序，客户端必须按 request_id 关联。

失败错误码固定为：

| 值 | 中文含义 |
|---|---|
| INVALID_REQUEST | request_id 可读，但其余业务字段非法 |
| REJECTED | 格式正确，但被余额、权限或服务策略拒绝 |
| INTERNAL_ERROR | Backend、Dispatcher 或内部处理失败 |

无法读出安全编号的 Wire 错误不构造响应。普通业务失败不关闭 Stream。

## 2. Channel 与订阅状态

- Channel 必须是非空 UTF-8 字符串，按 UTF-8 字节精确比较，区分大小写。
- SDK 不裁剪空白，不做 Unicode 归一化。
- * 是唯一特殊名称，只能用于 Subscribe/Unsubscribe，或作为唯一的列表元素。
- Publish 不能使用 *。
- 重复 Subscribe/Unsubscribe 是幂等状态操作，但每个被接受的新 request_id 仍可按配置收费。

状态转换：

| 当前状态 | 操作 | 新状态 |
|---|---|---|
| 任意 | Subscribe("*") | ["*"] |
| ["*"] | Subscribe(channel) | ["*"] |
| 普通集合 | Subscribe(channel) | 加入并排序 |
| ["*"] | Unsubscribe(channel) | ["*"] |
| 普通集合 | Unsubscribe(channel) | 移除并排序 |
| 任意 | Unsubscribe("*") | [] |

服务端按已认证 remote_public_key 保存订阅集合。Publish 只向当前在线且匹配的身份
尽力发送，每个身份最多一次；发送者的成功结果不包含收件人数量、身份或送达结果。

## 3. 精确计费

charged_amount 是 CBOR text string，内容为规范 ASCII 十进制：

~~~text
合法：0、1、12、0.1、0.001、12.34、0.123456789012345678
非法：-1、+1、00.1、1.0、1.2300、.1、1.、1e-3、19 位小数
~~~

最多 64 字节、最多 18 位小数；免费和失败固定为 "0"。V1 不重复编码货币名称或单位，
单位由部署的 SPI/计费配置约定。SDK 不将金额转换成二进制浮点或 JavaScript number。

SPI 的 `balance`/`amount` 是最小单位的 `uint64`，小于该单位的 SSP 金额必须由应用层用
固定 scale 的整数账本保存和结算，不能在 SPI 边界进行浮点转换或舍入。具体规则见
[SPI 集成与金额换算](./SPI集成与金额换算.md)。

调用者必须在 Backend/Dispatcher 内保证原子边界：

- Subscribe/Unsubscribe 的检查、扣费和状态写入在同一事务中；
- SubscriptionsRequest 的扣费和列表读取在同一事务中，响应返回该事务读取的列表；
- Publish 的扣费与“接受并开始广播”是同一接受动作；
- 业务失败不扣费、不留下部分状态；并发修改同一账户时使用行锁或等价串行化机制。

## 4. 并发、重复和 Session

每条 Stream 使用一个 Session。Session 在任何业务调用前原子登记 request_id：

~~~text
新编号       → 登记、执行业务、返回一条结果
重复编号     → 静默丢弃，不执行、不扣费、不响应、不返回历史结果
不同编号     → 可以并行，响应按完成顺序返回
~~~

Session 的编号集合只在该 Stream 生命周期内有效。Stream 更换后相同编号会作为新请求执行。
单个 Session 最多登记 65536 个不同编号；第 65537 个新编号返回本地 SESSION_LIMIT，
外部应用可以结束旧 Stream 并建立新 Stream。SDK 不实现传输层写队列，外部应用必须使用
串行 writer 写出完整响应。

如果 Subscribe 后依赖其结果查询列表，客户端应先收到并处理对应 ActionResult，再发送
SubscriptionsRequest；不同编号可并行不代表有依赖的操作会自动建立顺序。

## 5. 非目标

SSP V1 不定义：

- channel 管理、枚举、元数据、所有者或权限模型；
- 收件人列表、收件人数、送达 Ack、退款或“至少一人收到”的承诺；
- 历史消息、离线队列、补发、结果缓存、结果查询或重放；
- 跨 Stream 去重、断线恢复和幂等恢复；
- 正则、前缀、层级通配和 * 排除项；
- 价格配置文件、余额、支付凭证、货币名称或 SPI Wire；
- HTTP、WebSocket、WebRTC、bitcoin-libp2p、分帧、握手、心跳和实际网络发送。

## 6. V1 固定限制

| 常量 | 数值 | 中文含义 |
|---|---:|---|
| RequestIDBytes / REQUEST_ID_BYTES | 32 | request_id 固定字节数 |
| MaxAmountBytes / MAX_AMOUNT_BYTES | 64 | 金额 ASCII 字节上限 |
| MaxAmountScale / MAX_AMOUNT_SCALE | 18 | 金额最大小数位数 |
| MaxRequestIDsPerSession / MAX_REQUEST_IDS_PER_SESSION | 65536 | 单 Stream 编号上限 |
| MaxWireBytes / MAX_WIRE_BYTES | 1048576 | 完整 Wire 最大字节数 |
| MaxDocumentBytes / MAX_DOCUMENT_BYTES | 1048512 | 内层 document 最大字节数 |
| MaxChannelUTF8Bytes / MAX_CHANNEL_UTF8_BYTES | 256 | channel UTF-8 最大字节数 |
| MaxContentJSONBytes / MAX_CONTENT_JSON_BYTES | 1048000 | JSON 原始字节最大长度 |
| MaxSubscriptions / MAX_SUBSCRIPTIONS | 1024 | 订阅集合最大元素数 |
