# SSP V1 请求响应与精确计费改造施工单

> 状态：已完成，代码与验收门禁已通过。
>
> 前置实现：[001-SSP-V1-Go-TypeScript 双语 SDK 施工单](./001-SSP-V1-Go-TypeScript双语SDK施工单.md)
>
> 本单是 V1 正式发布前的协议改版。仓库当前没有 V1 tag，因此直接修订 V1，不保留旧 Wire
> 的兼容解码。施工完成后，CDDL、文档、fixture、Go 和 TypeScript 才能重新声明为冻结状态。

## 0. 改造结论

只增加解决“并行请求如何关联”和“实际扣费如何观察”所必需的能力：

1. 四种客户端请求都携带 32 字节 `request_id`（请求编号）；
2. Publish、Subscribe、Unsubscribe 成功后返回统一 `ActionResult`（动作结果）；
3. SubscriptionsRequest 成功后仍返回 SubscriptionsResponse，但响应带原 `request_id` 和
   `charged_amount`（实际扣费金额）；
4. 可识别请求编号的业务失败也返回 ActionResult，普通失败不关闭整条 Stream；
5. `charged_amount` 支持小于最小单位的小数，但使用精确十进制字符串编码，不使用
   IEEE 754 float；
6. 同一 Stream 可以并行处理不同请求编号，响应允许乱序，以 `request_id` 关联；
7. 同一 Stream 重复出现相同 `request_id` 时静默丢弃：不执行、不扣费、不响应；
8. Publish 成功只表示服务端已接受、已扣费并开始广播，不保证任何订阅者实际收到。

不新增收件人列表、送达回执、退款、历史消息、离线队列、结果查询、结果缓存或跨 Stream
幂等恢复。

## 1. Wire 定稿

外层 Wire 保持不变：

```text
[wire_version, wire_kind, document_cbor]
```

Kind 调整为六种：

| Kind | 英文名称 | 中文含义 | 方向 |
|---:|---|---|---|
| 1 | `Publish` | 发布请求或向订阅者交付广播 | 双向 |
| 2 | `Subscribe` | 订阅一个 channel 或全部 channel | 客户端 → 服务端 |
| 3 | `Unsubscribe` | 取消一个 channel 或全部订阅 | 客户端 → 服务端 |
| 4 | `SubscriptionsRequest` | 查询当前已订阅列表 | 客户端 → 服务端 |
| 5 | `SubscriptionsResponse` | 返回已订阅列表和本次扣费 | 服务端 → 客户端 |
| 6 | `ActionResult` | 返回动作成功/失败和本次扣费 | 服务端 → 客户端 |

内层文档固定为：

```text
Publish = [
  request_id,       // 请求编号，固定 32 字节
  channel,          // 发布 channel，不能是 "*"
  content_json      // 一份完整 JSON 文本的 UTF-8 exact bytes
]

Subscribe = [
  request_id,       // 请求编号，固定 32 字节
  channel           // 订阅 channel，允许 "*"
]

Unsubscribe = [
  request_id,       // 请求编号，固定 32 字节
  channel           // 取消订阅 channel，允许 "*"
]

SubscriptionsRequest = [
  request_id        // 请求编号，固定 32 字节
]

SubscriptionsResponse = [
  request_id,       // 原样返回请求中的编号
  charged_amount,   // 本次实际扣费金额
  channels          // 当前已订阅集合
]

ActionResult = [
  request_id,       // 原样返回请求中的编号
  success,          // true 成功；false 失败
  charged_amount,   // 本次实际扣费金额；失败固定为 "0"
  error_code        // 成功固定为 ""；失败为稳定错误码
]
```

ActionResult 只用于 Publish、Subscribe、Unsubscribe 的成功响应，以及四种请求的失败响应。
SubscriptionsRequest 成功只返回一条 SubscriptionsResponse，不再附加 ActionResult。

## 2. 字段和规范值

| 线上字段 | 类型 | 中文含义 |
|---|---|---|
| `request_id` | CBOR bstr，固定 32 字节 | 同一 Stream 内关联请求与响应的编号 |
| `success` | CBOR bool | 动作是否成功 |
| `charged_amount` | CBOR tstr，1..64 ASCII 字节 | 以部署计费最小单位表示的实际扣费数量，可含小数 |
| `error_code` | 固定 CBOR tstr | 客户端可稳定判断的失败分类；成功为空字符串 |
| `channels` | CBOR tstr 数组 | 规范排序后的已订阅集合 |

### 2.1 request_id

- 客户端生成不可预测的 32 字节值；SDK 可以提供安全随机生成辅助函数；
- 请求和对应响应逐字节使用相同值；
- 编号只用于同一 Stream 内的并行关联，不是广播消息 ID；
- 编号不提供跨 Stream 幂等、断线恢复或结果查询；
- 相同编号在另一条新 Stream 中是一个新请求，可以再次执行和扣费；
- 订阅者收到 Publish 广播时忽略其中的 `request_id`，不能据此要求发布结果或退款。

### 2.2 charged_amount

金额的业务目标是允许 `0.001` 这类“小于一个最小单位”的计费。Wire 使用字符串是为了让
Go、TypeScript、数据库和 SPI 应用得到完全相同的数值，避免二进制浮点舍入误差。

规范形式：

```text
0
1
12
0.1
0.001
12.34
```

拒绝：

```text
-1       // 不允许负数
+1       // 不允许正号
00.1     // 不允许多余前导零
1.0      // 末尾零必须规范化为 1
1.2300   // 末尾零必须规范化为 1.23
.1       // 必须写成 0.1
1.       // 小数点后不能为空
1e-3     // 不允许指数形式
```

固定规则：

- 最多 18 位小数，完整字符串最多 64 字节；
- 免费固定编码为 `"0"`；
- 失败结果固定编码为 `"0"`；
- V1 不在每条响应中重复货币或单位；部署只使用一套计费资产配置；
- 缺省单位是该部署在 SPI/计费配置中指定资产的最小单位；
- `"0.001"` 表示该最小单位的千分之一；
- Publish、Subscribe、Unsubscribe、SubscriptionsRequest 的配置价格可以分别为零或小额；
- 配置文件格式属于使用 SSP 的服务程序，不进入 SSP Wire，也不由核心 SDK 读取。

### 2.3 error_code

V1 只定义三个失败值，不携带英文错误消息或内部异常文本：

| 值 | 中文含义 |
|---|---|
| `INVALID_REQUEST` | 请求编号可读，但其他业务字段无效 |
| `REJECTED` | 请求格式正确，但因余额、权限或服务策略被拒绝 |
| `INTERNAL_ERROR` | 服务端 Backend、Dispatcher 或内部处理失败 |

成功时 `success = true`、`error_code = ""`；失败时 `success = false`、
`charged_amount = "0"` 且错误码必须是上表之一。其他组合属于非法 Wire。

## 3. 收费语义

每个新的请求编号按服务程序配置定价。Subscribe 或 Unsubscribe 即使没有改变集合，只要该
请求被接受，也可以收取配置金额；不引入 `changed` 字段和“没变化就免费”的特殊规则。

必须满足以下原子边界：

- Subscribe / Unsubscribe：检查、扣费和订阅状态写入在同一数据库事务内完成；
- SubscriptionsRequest：查询被接受和扣费在同一事务边界内，响应返回该事务读取的列表；
- Publish：扣费和“接受并进入广播处理”必须组成一个不可分割的接受动作；
- SPI Collect 与 SSP 扣费并发修改同一账户时，使用同一账户行锁或等价串行化事务；
- 业务失败不得扣费，也不得留下部分订阅状态；
- SDK 不引入 SPI 依赖，原子事务由调用者实现的 Backend / Dispatcher 保证。

Publish 的收费购买的是“服务端接受并开始广播”这个动作，不是“至少一个订阅者收到”。
服务端成功接受后，向在线订阅者的具体写入是 best-effort：某个接收者离线、写超时或连接
损坏，不改变发送者的成功结果，也不退款。响应不包含接收者数量和身份。

## 4. 重复编号和并行

### 4.1 重复编号

外部应用为每条 Stream 创建一个无网络依赖的 SSP Session。Session 原子登记第一次出现的
请求编号：

```text
第一次 request_id
  → 登记成功
  → 执行业务
  → 最终返回一条响应

同一 Stream 再次出现相同 request_id
  → 静默丢弃
  → 不执行业务
  → 不扣费
  → 不返回历史结果
  → 不返回任何新响应
```

Stream 结束时释放编号集合。V1 不保存结果内容，也不提供断线后的结果找回。响应在网络中
丢失后，客户端无法用相同编号取回；这是为保持 V1 简单而明确接受的限制。

为避免无限长 Stream 造成编号集合无限增长，固定：

```text
MaxRequestIDsPerSession = 65536
```

达到上限后，Session 拒绝登记新的编号并返回本地 `SESSION_LIMIT` 错误；外部连接应用应结束
该 Stream 并建立新 Stream。该错误不编码为 SSP ActionResult，因为旧 Session 已不能继续
保证编号唯一性。

### 4.2 并行处理

- 同一 Stream 中不同 `request_id` 可以并行执行；
- Session 锁只保护编号登记，不能把全部业务处理串行化；
- Backend 和 Dispatcher 必须支持并发并保证各自事务原子性；
- 多个响应可以按完成顺序返回，不保证与请求输入顺序相同；
- 外部长期连接应用必须通过一个串行 writer 写出完整响应，避免字节交错；
- 客户端通过 `request_id` 关联响应，不能依赖响应顺序；
- 如果操作有先后依赖，例如 Subscribe 后立即查询列表，客户端必须先收到 Subscribe 的
  ActionResult，再发送 SubscriptionsRequest。

本项目只规定以上调用契约，不实现 Protocol ID、长度前缀、Stream handler、写队列、
backpressure、WebSocket 或 bitcoin-libp2p 适配器。外部应用仍向 SDK 交付一个完整 SSP Wire。

## 5. 错误边界

能严格解析出合法 `request_id` 的业务失败，返回 ActionResult，不影响同一 Stream 中其他
请求：

```text
余额不足 → REJECTED，扣费 "0"，Stream 继续
权限拒绝 → REJECTED，扣费 "0"，Stream 继续
Backend 失败 → INTERNAL_ERROR，扣费 "0"，Stream 继续
```

无法安全构造响应的错误只返回给外部连接应用，不伪造 request_id：

```text
网络 frame 损坏
Wire 外层无法解析
request_id 缺失或长度错误
身份认证失效
Session 编号达到固定上限
```

是否结束连接由外部应用执行；SSP 核心 SDK 不操作 Stream。这里不再采用“普通计费失败就
reset 整条 Stream”的规则。

SDK 还必须保留原始错误 cause：

- Go 对 Backend / Dispatcher 错误包装稳定分类，同时 `errors.Is/As` 可找到原错误；
- TypeScript 的 `SSPError` 设置标准 `Error.cause`；
- Backend 返回非法订阅集合时，对外分类是 `BACKEND_FAILURE`，原始 cause 可以是
  `INVALID_SUBSCRIPTIONS`，不能伪装成客户端请求错误；
- ActionResult 只暴露本节固定的线上错误码，不泄漏 cause、堆栈或数据库文本。

## 6. Go 施工

### B01：protocol / wire

- 增加 `RequestID [32]byte` 和安全生成、复制、校验辅助函数；
- 增加不可变 `Amount` 类型，以规范十进制字符串保存，不提供 float64 构造接口；
- 增加 `ActionResult` 类型和 Kind 6；
- 四种请求文档加入 request_id；SubscriptionsResponse 加入 request_id 和 charged_amount；
- 严格实施金额规范、响应字段组合和 deterministic CBOR；
- 提供“解析外层和 request_id → 校验具体命令”的分阶段内部 API；同一份 Wire 只解析一次，
  既能在后续字段非法时返回 INVALID_REQUEST，也避免应用为计费和授权重复解析大报文；
- 增加 `MaxAmountBytes = 64`、`MaxAmountScale = 18`、
  `MaxRequestIDsPerSession = 65536`；
- 重新计算并冻结受文档增长影响的 Wire / document / content 长度关系。

客户端 API 调整为：

```go
NewPublish(requestID, channel, contentJSON) ([]byte, error)
NewSubscribe(requestID, channel) ([]byte, error)
NewUnsubscribe(requestID, channel) ([]byte, error)
NewSubscriptionsRequest(requestID) ([]byte, error)
ParsePublish(wireCBOR) (protocol.Publish, error)
ParseActionResult(wireCBOR) (protocol.ActionResult, error)
ParseSubscriptionsResponse(wireCBOR) (protocol.SubscriptionsResponse, error)
```

旧的无 request_id 构造函数签名直接删除，不保留自动生成编号的重载，避免调用者无法管理并行
响应。可以另提供 `NewRequestID()` 安全辅助函数。

### B02：Backend / Dispatcher

接口返回本次实际扣费金额：

```go
type Backend interface {
    Subscribe(ctx, publicKey, requestID, channel) (chargedAmount protocol.Amount, err error)
    Unsubscribe(ctx, publicKey, requestID, channel) (chargedAmount protocol.Amount, err error)
    Subscriptions(ctx, publicKey, requestID) (channels []string, chargedAmount protocol.Amount, err error)
}

type Dispatcher interface {
    Dispatch(ctx, event PublishEvent) (chargedAmount protocol.Amount, err error)
}
```

Backend / Dispatcher 从服务程序配置读取价格并执行收费，但 SSP SDK 不解析配置文件、不调用
SPI。接口成功返回的金额必须是实际已扣金额，而不是报价。

### B03：Session 服务入口

新增每 Stream 一个的无网络 Session：

```go
session := service.NewSession(remotePublicKey, backend, dispatcher)
result, err := session.HandleMessage(ctx, completeWire)
session.Close()
```

`result` 明确区分：

```go
Response   []byte // 需要外部应用写回的完整 Wire
HasResponse bool  // 是否存在响应
Suppressed  bool  // 是否因重复 request_id 被静默丢弃
```

Session 必须并发安全。第一次编号登记发生在调用业务接口之前；重复调用不能进入 Backend 或
Dispatcher。`Close` 释放编号集合，之后调用返回本地 Session closed 错误。

Go 业务失败如果已经成功构造失败 `ActionResult`，必须在 `Result.Cause` 中保留本地错误并
返回 `error == nil`，确保连接层先写回响应；只有无法安全构造响应的格式、身份、Session
或内部编码错误才返回非空 `error`。

## 7. TypeScript 施工

与 Go 保持完全同义：

```ts
type RequestId = Uint8Array; // 运行时严格校验 32 字节并复制
type Amount = string;        // 运行时严格校验规范十进制

newPublish(requestId, channel, contentJson): Uint8Array
newSubscribe(requestId, channel): Uint8Array
newUnsubscribe(requestId, channel): Uint8Array
newSubscriptionsRequest(requestId): Uint8Array
parsePublish(wireCbor): Publish
parseActionResult(wireCbor): ActionResult
parseSubscriptionsResponse(wireCbor): SubscriptionsResponse
```

- `newRequestId()` 使用 Web Crypto / Node 支持的标准安全随机源，不使用 `Math.random()`；
- 所有 requestId、contentJson、Wire 输入输出均防御性复制；
- `SSPError` 构造函数接收 `{ cause }` 并保留原异常；
- Backend / Dispatcher 返回实际 `Amount`；
- 新增并发安全语义的 `Session`，第一次编号登记同步完成，再执行异步业务；
- TypeScript Session 返回 `{ response?, suppressed }`；
- 不依赖 Node Buffer、libp2p、WebSocket、HTTP 或 SPI SDK。

- 不引入 `/home/david/Workspaces/bitcoin-libp2p`、SPI 或其类型依赖；

- 不为每个内部异常增加协议错误码。

## 12. 完成定义

只有同时满足以下条件，002 才能标记完成：

- 六种 Kind 的 CDDL、fixture、Go、TypeScript 和正式文档完全一致；
- 四种请求都有 request_id，所有成功请求恰好返回一条带实际金额的响应；
- 普通业务失败返回失败 ActionResult，不影响同 Stream 的其他请求；
- 重复 request_id 不执行、不收费、不响应，也不缓存历史结果；
- charged_amount 可以精确表示小于最小单位的小数，免费为 `"0"`；
- Subscribe / Unsubscribe 的收费不依赖状态是否变化；
- Publish 成功只承诺接受、扣费和开始广播，不包含任何接收结果；
- 收费与订阅状态/Publish 接受处于调用者 Backend 的同一原子边界；
- Backend / Dispatcher 原始 cause 可追溯且不泄漏到 Wire；
- 同 Stream 不同编号可并行，响应可乱序，客户端按编号关联；
- Go、TypeScript、CDDL、跨语言、race、示例和打包门禁全部通过；
- 依赖树和仓库中仍不存在 SPI、HTTP、WebSocket 或 bitcoin-libp2p 适配实现。

## 13. 给三方引用者的简短说明

> 我们接受“付费动作需要可观察结果”和“Backend/Dispatcher 应保留原始 cause”两项意见。
> SSP V1 会为所有请求加入 32 字节 request_id；Publish、Subscribe、Unsubscribe 返回统一
> ActionResult，订阅列表响应也回显 request_id。每个成功响应都携带实际 charged_amount，
> 免费为 0；金额允许小于最小单位，但以规范十进制字符串编码，避免跨语言浮点误差。
>
> 同一 Stream 允许不同 request_id 并行，响应按 request_id 关联。重复 request_id 在该
> Stream 内静默丢弃，不执行、不收费，也不缓存或重放第一次结果。收费价格来自服务配置；
> 重复但使用新 request_id 的 Subscribe/Unsubscribe 仍按配置收费，不增加 changed 规则。
>
> Publish 成功表示服务端已接受、已扣费并开始广播，不承诺任意接收者已收到，也不返回
> 接收者信息。普通余额或业务拒绝返回失败结果，不关闭整条 Stream。收费与订阅状态变更/
> Publish 接受必须由调用者在同一事务边界完成。
>
> 为保持 V1 最小化，本项目仍不实现 libp2p/HTTP/WebSocket 适配，不增加送达回执、离线
> 队列、退款、结果查询或跨 Stream 幂等恢复；外部长期连接继续向 SSP SDK 交付完整 Wire。
